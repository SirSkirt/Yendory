Games

Small text games a Yendory model plays through Nexus: it sees the game's rules, looks to see the position, makes a move, and gets the result back, the way it will later use apps. Every game has a perfect player, so every move the model makes can be graded.

Play

A game between the open model and the perfect player, a random player, or you. Step through it turn by turn and see what the model wrote: the actions it took, the results it got, and how each move compares with the perfect player's.

The game, as the model saw it

Lessons

The perfect player's turns, written as lessons: in each, it looks, makes the best move and replies, exactly as the model will be asked to. One position in ten is held out and never written, so the Scoreboard can tell whether a model plays well where it was never taught.

Teaching

Tools will teach these lessons through the Yendory Network once the Network can train (its training job is on the way); the Hub will update the Network, and this button will start. Until then, the saved file is a Multi-Turn Conversation lesson, the format Studio's Classroom reads, with Nexus's Environment, Action and Result lines.

Scoreboard

The open model plays a game many times, half the games going first. Every move is graded: legal or not, and whether it is the perfect player's. The last columns count only held-out positions, never in any lesson, so they show what the model learned rather than what it memorised.

Train

The open model learns a game by imitation (generation 0): from your recordings, the controls you used after each picture. Recordings marked for testing are never trained on; the network is measured on them, beside the frequency baseline, which uses each control as often as you did but never looks at the picture. Only a network that beats that baseline has learned something from what it sees.

Generations: learning from its own play

Imitation teaches the basics from your play. Generations go on from there: each generation, the champion (the accepted weights) and copies of it with small random changes play the same new layouts; the game's score picks the best episodes; the best player learns from them, mixed with your recordings so the basics stay; then the new network and the champion play layouts nobody has played. Only a better score makes the new network the champion; a generation that does worse changes nothing. The score only picks which play to learn from: the network never sees it.

Checks

Each phase of game training can be checked on its own, on this computer. The automatic checks use the test range (Tools starts it) and send input only through the safety layer; the steps after them need you.

Phase 2: the game's picture, virtual input, safety

Leave the keyboard and mouse alone while it runs (about 15 seconds). For the stop keys: press the button, then press Ctrl+Alt+End within 15 seconds.

    Phase 3: recording your play

    First record yourself on 2.3 for half a minute (walk, turn, click); the checks look at your latest recording of the game. Then open it on 2.4 and play it back: the controls should follow what you did.

      Phase 4: the network, training, playing

      The training check uses the open model's skill for the game. Then by hand: record several minutes on the range (2.3), some marked for testing; open a model, add the range skill and train it (2.5) until its held-out loss is clearly below the baseline; then measure it on the range (2.6). It has learned when it beats both the untrained network and the frequency baseline.
